# ブランチ開発グラフ

既存の Current Repository / Current Branch / Fetch Origin の直下に挿入する任意のパネルです。Changes / History、差分、コミット操作は従来の画面を利用します。

## 操作

- ヘッダーから折りたたみ・再表示・再読み込み・表示設定を操作できます。
- 下端をドラッグ、またはフォーカスして上下キーで高さを変更します。通常画面の領域を残すため画面高に対する上限もあります。
- 横スクロールは履歴、縦スクロールはブランチです。初回は現在側を表示します。
- ブランチ名または線をクリックすると既存のチェックアウト処理を実行します。未コミット変更や競合の扱いは既存の確認画面に従います。
- 右クリックで現在のブランチへのマージ、比較、名前変更、削除、現在のブランチのPushができます。マージと削除は既存のダイアログを開きます。
- コミットをクリック、またはフォーカスしてEnter/Spaceを押すと、チェックアウトせずHistoryの差分表示で確認できます。
- ◆はDesktopが管理するStashです。クリックで必要に応じてブランチを切り替え、そのブランチのStashを開きます。チェックアウトが確認画面で保留・中止された場合は別ブランチのStashを開きません。保留の確認を完了した後はマーカーをもう一度選択してください。
- ブランチへのマウス移動またはキーボードフォーカスで右側の情報欄を更新します。最新日時・コミット、共通履歴、PRの本文とLabelsを確認できます。

## 履歴と状態の意味

実線は実在するコミットの親子関係だけを示します。main、master、development/develop、既定ブランチを優先して、第一親の履歴を行に割り当てます。破線と白丸は現在の参照への案内であり、新しいコミットやマージを意味しません。選択中の行は強調、30日以上更新がない行と合流済みの行は薄く表示します。

基準ブランチはmain（ローカル優先）、master、既定ブランチの順です。「合流済み」は先端がその基準から到達可能であることをGitで確認した状態です。通常のマージの第二親から合流線を描画できます。Squash/Rebase MergeのPRがマージ済みでも、Git上で到達できない場合は実線で合流させません。PRのマージ状態は情報欄に独立して表示します。

時間は左から右への親子関係順です。コミット日時の時計ずれがあっても親が左になるよう並べます。等比例の日時軸ではありません。最新日時はコミットのコミッター日時です。

## 設定と取得範囲

表示状態、高さ、各グループ、ブランチ個別の表示設定はリポジトリパスごとに保存します。個別設定が最優先で、現在のブランチ、主要ブランチ、休止中、合流済み／未マージの順に判定します。設定変更はGit参照を変更しません。

初回は最大2,000件の履歴に加えて各ブランチの先端を取得します。古い履歴は2,000件ずつ最大10,000件まで追加できます。読み込み範囲外の親子関係は補完しません。古い先端だけが見えていて分岐元が範囲外の場合もあります。

Gitは一般にブランチの作成日時や削除済みの名前を記録し続けません。このため、主要ブランチ以外の行順は取得できた固有の第一親履歴の古さを使う近似です。参照名が残っていない合流履歴は「履歴 SHA（名前不明）」の行として残し、表示設定で切り替えます。「名前不明」は必ずしも削除されたブランチだと断定するものではありません。到達不能になり回収されたコミットは復元しません。

PRは既存の認証経路で最近更新された最大100件を取得し、ブランチ名とheadリポジトリを照合します。閉じたPRは先端SHAも照合し、同名ブランチの再利用と混同しないようにしています。PR本文は既存のSandboxedMarkdownで表示します。開発内容・テスト内容はPRに記載された内容であり、自動推測しません。

GitHubに接続できなくてもローカルグラフは動作します。取得済みのPR情報や既存のオープンPRキャッシュがあれば利用し、それ以外はコミット情報を表示します。Desktop管理外のStashはブランチとの対応を保証できないため今回のマーカーには含めません。

リモート最優先モードやローカル変更を無視する同期処理は含みません。

- `node --test script/desktop-jp/*.test.mjs`: 24件成功。実Gitリポジトリで通常マージ・削除済み参照・Squash Mergeを検証。時計ずれ、欠けた親、同一先端、空履歴、保存設定の破損、古いブランチの先端も検証。
- React/jsdomのコンポーネントテストでブランチ切り替え、マージダイアログへの委譲、コミット確認、設定保存、折りたたみ、オフライン表示を確認。GitHubとGitの取得はこのUIテストでは固定データです。
- 変更したTypeScript/TSXのESLint、グラフSCSSのコンパイル、差分の空白検査を実施。
- 全体の型チェックは同じnpm依存環境の変更前コードとの比較で追加診断なし。既存のReact型などによる30件の診断が残っており、全体成功とはしていません。
- `yarn build:dev`は初回メモリ不足。上限6GBで再試行しコンパイル段階まで進みましたが、通知モジュールの準備不足と既存の型エラーで全体ビルドは未成功。npmで検証依存を準備した環境であり、lockfileどおりの公式ビルド確認の代替ではありません。
- Windows/macOSのパッケージ起動、実画面の寸法・テーマ・キーボード操作、実アカウントでのPR取得、未コミット変更を含む確認・取消フローは実機確認が必要です。
