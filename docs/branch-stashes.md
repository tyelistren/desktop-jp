# ブランチごとのStash

Desktopで作成したStashをブランチ名に関連付け、同じブランチに複数件保存できます。
新しいStashを作成しても、以前のStashは削除されません。

## 使い方

1. 作業中の変更を通常のStash操作で退避します。
2. 別のブランチに切り替えても、元のブランチのStashは保持されます。
3. 「Stashした変更」を開くと、現在のブランチのStashを新しい順に選択できます。
   番号とコミットSHAで区別し、ファイル一覧・差分で内容を確認します。
4. 「復元」は選択した1件だけを復元します。正常に復元できた場合だけ、その1件を削除します。
5. 「破棄」は選択した1件だけが対象です。既存の破棄確認設定を引き継ぎます。

ブランチ切り替え時の「変更を現在のブランチに残す」も追加保存になります。
退避に失敗した場合は切り替えを中止します。変更を別ブランチに持っていく操作や、
保護ブランチ・detached HEADでの従来の切り替え規則は維持しています。
切り替えただけではStashを自動復元しません。

## 復元時の競合

競合や復元失敗が発生した場合、元のStashを残します。
競合を解消して内容を確認した後、不要になったStashを手動で破棄してください。
競合解消後に同じStashを再度復元する必要はありません。
保存元とは異なるブランチへの復元は拒否します。

## 保存形式と互換性

通常のGitの `refs/stash` と既存のDesktop用ブランチ識別子を使います。
ブランチごとに別のGitスタックを作るのではなく、表示・選択をブランチ単位に分離します。
既存のDesktop用Stashもそのまま対象になり、移行操作は不要です。
CLIなどで作成したDesktop識別子のないStashは一覧に追加せず、そのまま保持します。

アプリ内でブランチ名を変更すると、そのブランチの全Stashを新しい名前に関連付けます。
選択中のStashはアプリ実行中のみブランチ別に記憶し、再起動後は最新の1件を選択します。
新しいStashを保存したときも最新の1件に切り替わります。
ブランチ削除ではStashを削除しません。同じ名前のブランチを作り直すか、Git CLIで確認できます。
外部ツールによるブランチ名変更の自動追跡や、削除済みブランチ専用の管理画面はありません。
Git CLIや別プロセスと同時にStashを変更する操作全体をロックするものではありません。

## 検証

`script/desktop-jp/branch-stash.test.mjs` は本番のTypeScriptを読み込み、
Git実行部分を実際のシステムGitに接続して次を検証します。

- A・B両ブランチの複数Stash、古い1件の復元、別ブランチへの誤復元防止
- 競合と未コミット変更による復元失敗時の保持
- 変更なしの退避、CLIのStashの保持、名前変更後の順序・内容
- 本番Storeのブランチ別選択、選択済みStash削除後の次の候補
- 退避失敗時のチェックアウト中止
- UIコンポーネントの一覧、選択・復元の対象、破棄確認、処理中の無効化

UIテストはコンポーネントの出力とハンドラーを検証します。
配布版Electronでの見た目・操作確認は別途必要です。
